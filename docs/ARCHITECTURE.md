# Архитектура Atelier Commerce

Самостоятельный проект портфолио с Python backend. FastAPI проверяет HTTP и Pydantic-модели, SQLAlchemy управляет транзакциями и доступом к PostgreSQL. JavaScript показывает каталог и хранит временную корзину в памяти браузера. SQLite используется в быстрых тестах, PostgreSQL — в Compose и отдельном конкурентном CI-тесте.

Клиент отправляет только ID товаров и количество. Сервер сам читает цену и остаток: подмена суммы в браузере не влияет на заказ. OrderItem сохраняет название и цену на момент оформления, поэтому дальнейшее изменение каталога не меняет историю. Деньги — целые копейки; общий итог — BigInteger.

Оформление работает в одной транзакции: проверка ключа повторного запроса → чтение товаров по возрастанию ID с блокировками строк → условное уменьшение stock → создание заказа и снимков строк → commit. Если второго товара не хватает, rollback возвращает изменения первого. Сортировка блокировок уменьшает вероятность взаимоблокировки. Конкурентный тест PostgreSQL проверяет, что последнюю единицу получает только один из двух покупателей.

Ключ идемпотентности уникален в пределах пользователя. С ним хранится SHA-256 нормализованного запроса. Повтор с тем же содержимым возвращает существующий заказ, с другим — конфликт. При одновременной вставке одинакового ключа ограничение БД отклоняет дубль, транзакция откатывается; клиент может повторить тот же запрос. Это не платёжная интеграция: реальные деньги не списываются.

Отмена блокирует строку заказа и возвращает остатки один раз; повторная отмена не меняет склад. Отправленный заказ отменять нельзя. Клиент видит только свои заказы, административные маршруты проверяют is_admin на сервере. Регистрация не принимает привилегии от браузера.

Сессия — случайный токен в HttpOnly/SameSite cookie; в БД хранится только хеш. Пароль — scrypt с индивидуальной солью. Проверка Origin защищает изменяющие запросы, тело ограничено 64 KiB. Перед публичной эксплуатацией нужны ограничения параллелизма хеширования, общий rate limiter, восстановление пароля, журналирование и процедуры резервирования.

Обновление: GET /api/products, /api/orders и /api/admin/orders принимают offset (0+) и limit (1–100, default 24), возвращают массив и X-Total-Count. Сортировка стабильна по id; счётчик заказов ограничен владельцем, для администратора — все заказы. Миграции: [MIGRATIONS.md](MIGRATIONS.md). Публичный запуск остаётся вне проверенной области MVP.
