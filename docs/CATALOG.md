# Поиск и страницы каталога

`GET /api/catalog?q=&category=&min_price=0&max_price=100000000&in_stock=false&limit=24&cursor=`

Цены API передаются в копейках, интерфейс принимает рубли. limit 1–100. Поиск по названию/описанию выполняется сервером без учёта регистра; `%` и `_` трактуются как обычные символы. Категория сравнивается точно, диапазон цены включителен. Ответ: `{items: [...], next_cursor: string|null}`.

Курсор содержит последний ID, верхнюю границу ID при первом запросе и отпечаток фильтров. Следующая страница использует `id > after AND id <= ceiling`, поэтому добавление новых товаров не смещает уже начатый обход. Изменение фильтров требует нового обхода; некорректный курсор даёт 400. Сортировка — ID по возрастанию. Курсор не является секретом или средством авторизации. Это стабильная граница вставок, не снимок транзакции: изменения цены, активности и удаление товара между запросами могут изменить состав результата.

Ранее существовавшие `/api/products`, `/api/orders`, `/api/admin/orders` сохраняют offset/limit для совместимости; интерфейс каталога использует cursor API, история заказов — offset. Для большого каталога подстрочный поиск потребует PostgreSQL trigram/полнотекстового индекса и измерений запросов; текущая реализация не заявляет нагрузочных гарантий.

Тесты: Unicode-поиск, литеральный `%`, категория/цена/остаток, отсутствие дублей, вставка между страницами, смена фильтров и повреждённый курсор. Этот же сценарий выполняется на PostgreSQL в каждой версии Python 3.12–3.14. Chromium ищет товар за пределами первой страницы и меняет категорию.
